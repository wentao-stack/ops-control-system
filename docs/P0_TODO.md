# P0 待辦事項（暫緩）

> 記錄日期：2026-08-15
> 狀態：暫緩 — 目前僅單一用戶（wentao），多用戶隔離風險低，優先完成前端體驗。
> 後續多用戶上線前必須完成。

## 1. 記憶與 RAG 的用戶隔離

**風險**: `save_memory` / `get_memories` 工具由模型傳入 `user` 參數，工具執行層未強制改為當前登入用戶；RAG 檢索時未按用戶篩選，可能跨用戶讀寫記憶。

**待做**:
- [ ] 從工具參數 schema 移除 `user`
- [ ] 服務端根據當前認證用戶注入用戶名，禁止模型指定身份
- [ ] RAG memory 數據按用戶過濾，或改為每用戶獨立 collection
- [ ] 補跨用戶讀寫、RAG 數據隔離的自動化測試

## 2. AgentRun 持久化狀態機

**風險**: 一次聊天運行沒有可恢復、可審計的持久化 Run 狀態。前端可停止生成，但長任務無法可靠恢復、取消或重試。

**待做**:
- [ ] 新增 `AgentRun` 與 `AgentStep` 模型
- [ ] 狀態：`queued` / `running` / `awaiting_approval` / `succeeded` / `failed` / `cancelled` / `timed_out`
- [ ] 支援請求取消、步驟級超時、有限重試與冪等鍵
- [ ] 斷線重連後可恢復查看執行進度
- [ ] 持久化輸入、輸出、目標資產、確認者、實際命令與驗證結果

## 3. 審計日誌記錄實際登入用戶

**風險**: 部分審計記錄寫入固定的 `agent` 而非實際登入用戶。

**待做**:
- [ ] 審計日誌記錄實際登入用戶
- [ ] 統一 `create_note`、`acknowledge_alert` 與巡檢建筆記的角色與確認規則
