# AI Agent 完成度评估与优化建议

> 评估日期：2026-08-14  
> 依据：当前项目代码、`AGENT_PLAN.md`、已部署管理页与公开 API 响应。

## 总览

AI Agent 已从聊天原型进入可执行运维助手阶段：聊天、工具调用、SSE 事件、权限确认、记忆、RAG 与 Runbook 单步执行均已落地。作为生产级运维 Agent，当前应优先补齐安全隔离与运行可靠性，而不是继续扩大工具数量。

| 维度 | 进度 | 判断 |
| --- | ---: | --- |
| 核心聊天、工具调用与 SSE UI | 85% | 已可实际使用 |
| 知识库、RAG 与 Runbook | 75% | 已有检索、引用、评测与同步；权限隔离待加强 |
| 安全与审计 | 55% | 已有权限、确认和日志；仍有高优先级缺口 |
| 可靠性与运维闭环 | 45% | 缺少持久化任务状态、Incident 和自动化运营 |
| 生产级运维 Agent 整体成熟度 | 约 60% | 先补安全可靠性，再扩功能 |

## 已完成能力

- 工具：约 16 个，覆盖资产/指标/服务/告警/笔记/变更查询、SSH 命令、Supervisor、记忆、RAG、Runbook 检索与单步执行。
- 交互：SSE 串流、工具进度、错误提示、对话持久化、停止生成、工具确认卡片与用量展示。
- 安全基础：`read` / `write` / `exec` 三级权限；高风险工具须管理员确认；确认请求绑定发起用户；工具调用会写入审计模型。
- 知识能力：长期记忆、Runbook、笔记和变更记录已接入 RAG；回答可显示检索引用；包含 RAG 重建和质量评测入口。
- 运维支持：LLM 健康检查、Token 用量统计和主动巡检 API 已实现。

## 优先优化项

### P0：强制记忆与 RAG 的用户隔离

当前 `save_memory` 与 `get_memories` 工具由模型传入 `user` 参数，工具执行层没有强制改为当前登录用户；RAG 也会纳入所有用户记忆，检索时未按用户筛选。此设计可能造成跨用户读取或写入记忆。

建议：

1. 从工具参数 schema 中移除 `user`。
2. 服务端根据当前认证用户注入用户名，禁止模型指定身份。
3. RAG 的 memory 数据按用户过滤，或改为每用户独立 collection。
4. 为跨用户读写、RAG 数据隔离补充自动化测试。

### P0：将任意 Shell 改为受控操作

目前依赖“命令黑名单 + 前端确认”。黑名单无法可靠防止命令变形、组合命令和高风险误操作。

建议：

1. 将重启服务、查日志、检查磁盘、检查部署等常用动作实现为参数白名单工具。
2. 任意 Shell 仅保留给明确的高权限角色，并限制资产环境、命令类别、超时和输出量。
3. 审计日志记录实际登录用户，而非固定的 `agent`。
4. 统一 `create_note`、`acknowledge_alert` 与巡检建笔记的角色和确认规则。

### P0：为 Agent 运行建立持久化状态机

一次聊天运行目前没有可恢复、可审计的持久化 Run 状态。前端可停止生成，确认等待也有超时，但长任务无法可靠恢复、取消或重试。

建议新增 `AgentRun` 与 `AgentStep`：

- 状态：`queued`、`running`、`awaiting_approval`、`succeeded`、`failed`、`cancelled`、`timed_out`。
- 支持请求取消、步骤级超时、有限重试和幂等键。
- 断线重连后可恢复查看执行进度。
- 持久化输入、输出、目标资产、确认者、实际命令与验证结果。

### P1：形成诊断—计划—执行—验证闭环

当前 Runbook 单步确认是良好基础，但尚未形成完整的事件处理工作台。

建议：

1. 新增 Incident：严重度、影响资产、关联告警/变更、负责人和时间线。
2. 执行前生成 Action Plan，展示证据来源、风险、步骤和回滚方案。
3. 执行后自动验证健康端点、服务状态与关键指标；失败时给出回滚建议。
4. 提供独立审计查询 API 与 UI，展示请求、确认、实际指令、输出与影响资产。

## 后续优化项

- 排程巡检、告警去重/静默/升级，以及 Telegram、Slack 或 Email 通知。
- RAG 加入数据权限、失效/删除校验、检索命中率监控与线上评测集。
- 用量统计加入费用估算、预算上限、异常调用告警和按模型/用户配额。
- 补齐端到端测试与 CI；当前环境缺少 `pytest`，尚未完成完整测试套件验证。
- 图片/Vision 与自定义工具管理，建议在上述安全可靠性工作完成后实施。

## 建议实施顺序

1. 记忆与 RAG 用户隔离。
2. Shell 受控化与写入操作授权策略统一。
3. `AgentRun` 状态机、取消/超时/重试与审计查询页。
4. Incident 和诊断—计划—执行—验证闭环。
5. 排程巡检、通知、配额和多模态能力。
